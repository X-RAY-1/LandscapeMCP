# v0.4 Apply contract

FlattenRectangle / FlattenPath / CreateWalkablePath の本実行（`bDryRun=false`）の挙動です。入力・高度profile・Result fieldの定義は [v0.4 Tool仕様](v0.4-tools.md) を参照してください。

## bDryRun

| bDryRun | 動作 |
|---|---|
| `true`（既定） | 検証・snapshot read・計画のみ。Landscape write、transaction、package dirty、saveなし。成功は `PREVIEW_READY` または `NO_CHANGE` |
| `false` | 検証後にLandscapeの高さを変更する。成功は `APPLIED`（変更あり）または `NO_CHANGE`（変更不要） |

Applyは1 requestにつき自分のtransactionを1つだけ作ります（`NO_CHANGE` と拒否は0）。Undo/Redoできます。Level・assetは保存せず、Editor設定も変更しません。packageはdirtyになります。

### Preview成功はApply受理を保証しない

DryRunは入力検証、対象Landscapeの基本条件、source geometryの計画だけを確認します。次はApplyでのみ検査するため、`PREVIEW_READY` の後でもApplyが拒否されることがあります。

- Editorのtransaction bufferがidleであること（`ACTIVE_TRANSACTION`）
- autosave無効・自動checkout無効・source control provider非active（`UNSUPPORTED_EDITOR_SAVE_POLICY`）
- Engine default materialのみ、Grass/Foliage cacheなし（`UNSUPPORTED_GRASS_STATE`）
- native mip0 collision、material position offset bakeなし（`UNSUPPORTED_COLLISION_STATE`）
- 現在のcollisionが独立予測と一致すること、計画後の予測collisionがwalkability条件を満たすこと（`UNSUPPORTED_COLLISION_STATE` / `CANNOT_SATISFY_WALKABILITY`）
- 書き込み直前の再検証で対象・source・collateralが計画時と同一であること（`STALE_PLAN`）
- rollback失敗後のlatch（`MUTATION_DISABLED_AFTER_ROLLBACK_FAILURE`）

DryRunのResultにある `PREVIEW_ONLY` warningと、CreateWalkablePathの `bWalkabilityGuaranteed` はsource geometryの計画についての記述です。collisionを含む確認はApplyが行います。

## Apply pipeline

検証 → 対象解決と安全条件 → source／collateral snapshot → retry cache照会 → 計画・量子化 → 現在のcollisionと独立予測の照合 → 計画後の予測collision → 書き込み直前の再検証 → 1 transactionで書き込み → fresh source・geometry・collateral・actual collisionの検証 → `APPLIED`。

書き込み後の検証に失敗した場合は、最新のundo entryが自分のtransactionであることを証明したうえでそれだけをUndoし、元のsource（halo込み完全一致）、identity、collateral、collisionを再検証します。すべて一致すれば `ROLLED_BACK` / `rollbackStatus=VERIFIED`、証明できなければ `ROLLBACK_FAILED` / `FAILED` とし、このmodule sessionでは新3 ToolのApplyを拒否します（DryRunと既存Toolは使用可）。解除はEditor再起動／module reloadのみで、公開の復旧APIはありません。

## Retry cache

同一requestの二重実行（timeoutによる再送など）で地形を二重に変更しないための、module内のbounded idempotency cacheです。安全性の根拠にも拒否の根拠にもしません。

- requestの全引数が完全一致するrecordがあり、**現在のsourceとtarget identityがそのrecordの検証済み結果と一致する**場合だけ、現在のcollisionを再検証したうえで `NO_CHANGE`（`modifiedCount=0`、write・transactionなし）を返します。対象解決とApply専用の安全条件はこの場合も毎回検査します。
- 一致しない場合（人がUndoした、別の編集が重なった等）、recordは現在の地形については無効として破棄し、通常の新しいApplyとして最初から検証・snapshot・計画・collision検証・直前再検証を行います。`Apply A → Undo → Apply A` と `Apply A → Apply B → Apply A` はどちらも現在の地形に対する再計画です。
- 容量は128 record、request 1件につき1 record。満杯時は最も古いrecordから破棄します（FIFO）。満杯でApplyが止まることはありません。
- recordが無い（破棄された）requestは新規requestと同じ扱いです。falloffを持つ編集は元の高さとのblendなので、**128件より古い同一requestの再送は再度blendされ、冪等になりません**。
- cacheはEditor再起動／module reloadで消えます。再起動を跨ぐ冪等性は保証しません。

## Collision検証

Sourceから独立に予測したChaos collision（component全域のmin/maxによるuint16再量子化、00-11 split）と、実際のphysicsへのline traceを、coreとtransitionの全native triangleで比較します。期待値をactualのcollision dataやtrace結果から作ることはありません。検証の間引きもしません。

- traceは三角形の重心を通る鉛直線（上下2000cm）の `ECC_WorldStatic` channel queryです。経路上の他のcomponent（StaticMesh、壁、岩、別のLandscape等）はidentityで判別して読み飛ばし、**対象Landscapeのそのcomponentのcollision** に到達したhitだけを検証します。hitしたActor・component・face・位置・法線・傾斜の許容誤差は従来と同じです。対象に到達しなければ失敗です。
- 1回の検証で読み飛ばせる他componentは256個までで、超えた場合は拒否します。
- 他componentは検証対象から除外するだけで、変更・移動はしません。propの下の地形を変更してもpropは追従しません。
- range=0（完全に平坦なcomponent）ではcollisionのpacked uint16値は保証対象外で、decodeしたgeometry（=min）が一致することを契約とします。
- 実測比較するのは変更に関わるcoreとtransitionの三角形です。同じcomponentの他の三角形も再量子化で最大1量子（Scale.Z/128 cm）未満動き得ますが、そこは予測モデルに依存し個別には実測しません。
- CreateWalkablePathは、source・予測collision・actual collisionの検証に加えて、各core三角形で `閾値 − max(source傾斜, 予測collision傾斜) − source誤差 − codec誤差 − 数値誤差 > 0` を要求します。`NEAR_LIMIT` は成功にしません。CharacterMovementやNavMeshでの通行は保証しません。

## Collateral検証の範囲

Applyは書き込み前・直前・書き込み後・rollback後に次を比較し、差があれば拒否またはrollbackします。

- 全LevelのActor一覧（順序、object identity、path）
- 対象以外の各ActorについてActor自身のserialized propertyのCRC（WorldSettingsを含む）
- 対象Landscapeのweightmap texture（source mipのCRC、identity、path）
- 対象Landscapeのtransform、edit layer、component構成、heightmap／collision componentのidentity

**含まないもの:** 他Actorのcomponent内部の状態（位置、instance transform、mesh等）、asset本体、対象以外のLandscapeのheightmap内容。これらは「変更経路を持たないこと」（Foliage付きLandscapeの拒否、対象Landscapeのtextureのみへの書き込み、Save／checkoutを行わないこと）で保護しており、Automationのfixtureで個別に確認していますが、Applyごとの網羅的な比較ではありません。「無関係なobjectがすべてbit単位で不変」とは主張しません。

## 診断

失敗時は公式MCPの `isError=true` とともにbounded JSON（profile配列を含まない）を返します: `errorCode` / `operation` / `stage` / `landscapePath` / `reason` / `mutationDisabled` / `message` / `rollbackStatus`。

`stage` は実際に拒否した処理段階で、message文字列からは決めません。DryRun: `validation` / `snapshot` / `planning`。Apply: `validation` / `safetyLatch` / `resolve` / `snapshot` / `retry` / `planning` / `beforeCollision` / `predictedCollision` / `preWrite` / `noChange` / `noChangeCollision` / `transaction` / `postSource` / `postGeometry` / `postCollision`。

## 現在の制限

- 単一の読み込み済み `ALandscape`（exact class・exact object path）。World Partition、Streaming Proxy、subclass、回転、Nanite、hole、複数／非標準edit layer、Blueprint brush、attached Foliageは拒否。
- Applyは上記「Preview成功はApply受理を保証しない」の条件を満たすEditor／Landscape状態のみ。custom material・Material Instance・Grassは未対応。
- 上限: path 2〜64点・長さ10000cm、幅／矩形辺5000cm、falloff 2500cm、maxDelta 1000cm、要求頂点16384、read頂点（halo込み）16384、profile 1024点、Landscape全体262144頂点・64 component。
- FlattenRectangleの `yawDegrees` は0のみ。
- retryの冪等性は直近128 requestかつ同一module session内。
- 計測値（Applyの所要時間等）は測定環境での実測で、上限保証ではありません。
